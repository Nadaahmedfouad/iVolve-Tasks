# Lab 9 – Kubernetes Cluster with kubeadm

In this lab, I set up a three-node Kubernetes cluster using Ubuntu VMs in VirtualBox. I used `kubeadm` to initialize the control plane, joined two worker nodes, and installed Calico for pod networking.

## Lab setup

| VM            | Role          | Host-only IP    |
| ------------- | ------------- | --------------- |
| `k8s-control` | Control plane | `192.168.56.10` |
| `k8s-worker1` | Worker        | `192.168.56.11` |
| `k8s-worker2` | Worker        | `192.168.56.12` |

- **OS:** Ubuntu 22.04
- **Container runtime:** containerd 2.2.1
- **Kubernetes:** v1.35.9
- **CNI:** Calico v3.33.0
- **Networking:** NAT for internet access and a VirtualBox host-only network for communication between nodes

## What I did

### 1. Prepared the VMs

I cloned an existing Ubuntu VM to create the control plane and two workers. I gave each VM its own hostname, machine ID, and static IP on the host-only network. I also expanded the disks, disabled swap, and configured the kernel settings required for Kubernetes networking.

### 2. Installed containerd and Kubernetes

On all three nodes, I installed containerd and configured it to use the `systemd` cgroup driver. Then I installed `kubeadm`, `kubelet`, and `kubectl` and set each node's kubelet IP to its host-only address.

### 3. Initialized the control plane

On `k8s-control`, I ran:

```bash
sudo kubeadm init \
  --apiserver-advertise-address=192.168.56.10 \
  --pod-network-cidr=10.244.0.0/16 \
  --cri-socket=unix:///run/containerd/containerd.sock
```

After initialization, I configured `kubectl` using `/etc/kubernetes/admin.conf`.

### 4. Installed Calico and joined the workers

I installed Calico for communication between pods across the nodes. The first installation had an issue: the Tigera Operator kept crashing because its native v3 CRD mode required a Kubernetes admission API that wasn't available in my cluster. I switched to the supported legacy v1 CRDs, recreated the Calico `Installation` resource, and the operator started working.

I configured Calico to use the nodes' Kubernetes internal IP addresses (`192.168.56.x`) instead of automatically picking the NAT interface.

Finally, I used the `kubeadm join` command generated by the control plane to add both workers. All three nodes reached **Ready** status.

## Testing the cluster

To check that the cluster could run applications, I deployed four Nginx replicas:

```bash
kubectl create namespace lab9
kubectl create deployment nginx --image=nginx:stable --replicas=4 -n lab9
kubectl get pods -n lab9 -o wide
```

Kubernetes placed two Nginx pods on each worker. I exposed the deployment through a ClusterIP Service and tested it from a separate curl pod. The request returned **HTTP 200 OK**.

I also deleted one Nginx pod to test self-healing. Kubernetes created a replacement automatically, and the deployment returned to **4/4 Ready**.
